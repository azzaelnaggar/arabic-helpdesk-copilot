## Which fields a model may use

| Role | Fields | Reason |
|---|---|---|
| Input | `title_ar`, `description_ar`, `channel`, `created_at` | Known the moment a ticket arrives |
| Target | `category_level_2` (16 classes) | The main task (L1 follows from L2) |
| Forbidden | `category_path`, `labels_json`, `tags` | They contain the label |
| Forbidden | `priority` | Computed from `urgency` and `impact` |
| Forbidden | `updated_at` | Written after the ticket is handled (future information) |
| Forbidden | `impact`, `sentiment` | Set by the generator, not by the person writing the ticket |
| No information | `model`, `dialect` | Same value in every row |

## How the split was made

1. Removed exact duplicates (same title **and** description): 10,000 → 9,549 tickets.
2. Built a template key for each ticket: the title plus the first sentence of the description, with every number replaced by `#`. This gives 3,548 template groups.
3. `GroupShuffleSplit` (seed 42) put about 70% of the groups into train and 30% into a temporary set. A second split, by groups, divided that temporary set in half into val and test.
4. Checks: no template group appears in more than one split, and all 16 L2 classes appear in every split.

## Audit findings

Measured in [`01_explore_data.ipynb`](../01_explore_data.ipynb). Numbers 1–11 refer to the raw 10,000 tickets; 12–13 refer to the de-duplicated 9,549.

1. `priority` uses school rounding of (impact + urgency) / 2, which matches 10,000 of 10,000 rows. Python's `round()` matches only 76.92%, because it rounds .5 to the nearest even number. Since `priority` is derived from `urgency`, it is excluded from model inputs.
2. All 14 tickets titled "مشكلة في الأوفيس" with the "License Error" template are labeled L3 = Crash, and no License-labeled ticket uses this text. Of the 88 tickets that mention "license", 74 are labeled License and 14 Crash. This is a systematic, template-level label error that metrics cannot detect. L2 (Office Apps) is not affected.
3. Tickets are built from templates: one core sentence, random slots (Office version, hours, building and floor), and random add-on sentences such as "محتاج الموضوع يتحل بسرعة". The exact-duplicate check misses these near-duplicates; for example, TCKT-001-206 and TCKT-001-440 are identical.
4. Only 1,665 distinct opening sentences appear in 10,000 descriptions. "المشكلة مستمرة من يومين" opens 1,155 of them (11.6%) and carries no category information: its L1 distribution is close to the overall one.
5. L1 classes are mildly imbalanced, from Access at 19.9% to Security at 12.0% (ratio ≈ 1.7). Use Macro-F1, not accuracy alone.
6. Category information lives mostly in the title. Generic descriptions carry none, except for category-specific sentences the generator injected (a WiFi network name, an Office version, the VPN code "Error 809").
7. Some generated texts are incoherent, e.g. "طلب لابتوب جديد" followed by "tried restart, same problem".
8. Perfect shortcut phrases: "نسخة الأوفيس" means Office Apps in 525 of 525 tickets, and "Error 809" means VPN in 111 of 111. Every model will be evaluated on both raw and cleaned text.
9. 1,187 descriptions (11.9%) consist only of "فيه مشكلة مرتبطة بـ L1 / L2 / L3" plus a fixed sentence, so the label is written inside the input.
10. Urgency is independent of the text. The 1,187 tickets that all say "محتاج يتحل بسرعة" are spread evenly over urgency 1–5 (256 / 210 / 233 / 242 / 246), so urgency is not a training target from this dataset.
11. In all 1,187 leak sentences, the label path written in the text is exactly the ticket's own label.
12. After removing exact duplicates, 9,549 tickets remain, and they come from 3,548 template groups.
13. The group split (GroupShuffleSplit, seed 42) gives train 6,512, val 1,586 and test 1,451. No template is shared across splits, and all 16 L2 classes appear in every split. Class proportions differ by up to about 3–4 percentage points, e.g. Incident is 6.3% of train and 3.9% of test.

## Found later, during baseline error analysis (Phase 2)

- Batches TCKT-008/011/013/014 (1,899 tickets, 19.9% of the de-duplicated data) have scrambled labels: 61–77% val error against at most 24% for every other batch, and their titles do not match their labels. Models are trained and scored without these batches; they will be dropped from test too.
- Urgency learnability check (finding 10 confirmed): random guessing 0.192, shuffled labels 0.205, real labels 0.206 val Macro-F1.

## Limitations

All tickets are synthetic. Even after cleaning, scores on this data say little about real helpdesk traffic. A small human-written challenge set (Phase 9) is planned for that reason.
